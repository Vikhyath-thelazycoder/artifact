# Project Decisions: ARTIFEX

These decisions are made and recorded. Changing one means adding a new row that supersedes the old one, not editing it.
The source specification is [ARTIFEX_ARCHITECTURE.md](../ARTIFEX_ARCHITECTURE.md). Where a decision here differs from that file, this file wins.

| ID | Date | Kind | Topic | Decision | Reason | Supersedes | Status |
|---|---|---|---|---|---|---|---|
| D-001 | 2026-10-25 | architecture | stack | Next.js 15 App Router on Vercel + Supabase (Postgres, Auth, Storage). TypeScript strict, Tailwind v4, Vitest | Server routes keep the Gemini key server-side and can inspect uploaded files. Same stack as the team's previous event app (`ai-mucial-chair`), so the patterns are known | Spec §4 "React + Vite" | ACTIVE |
| D-002 | 2026-10-25 | architecture | authority | Every state change (register, start, extend, end, submit, score, AI records, results, publish) runs in a Postgres security-definer RPC that checks role, state and the database clock | The browser is untrusted. One source of truth and one clock for everyone | — | ACTIVE |
| D-003 | 2026-10-25 | security | participant-identity | Participants sign in with USN + 6-digit PIN. The `participant-signup` Edge Function creates their auth account pre-confirmed, with a synthetic email `<usn>@participants.artifex.app`. Staff (admins, judges) use real email + password accounts listed in `staff` | No confirmation emails (the free tier sends 2 an hour). The service key stays inside Supabase | — | ACTIVE |
| D-004 | 2026-10-25 | product | round-timing | One shared round. `deadline_at = started_at + duration_seconds` (default 600). Late joiners get the remaining time only. The admin can extend globally (with a reason) or end early. No pause | Fairness: no per-device timers, no pause disputes in a 10-minute round | — | ACTIVE |
| D-005 | 2026-10-25 | product | deadline-policy | **Strict completion with a fixed network grace.** The upload and its finalisation must both reach the server by `deadline_at + grace_seconds` (default 10 s). Shown on the rules page and in the workspace | One rule for everyone, decided before the event (spec §7.5) | — | ACTIVE |
| D-006 | 2026-10-25 | product | files | PNG, JPG or PDF, 10 MB max, private bucket. One active submission per participant; replacing it before the deadline creates a new version (history kept) | Spec §10.1 recommendation | — | ACTIVE |
| D-007 | 2026-10-25 | product | judging-mode | The admin picks the judging mode per event: **Manual** (admin and judges score with the rubric) or **AI** (Gemini scores). The admin can cancel an AI run at any time and switch to manual. Publishing results is always an admin action | User decision: "the admin can do it manually or let the AI judge; the admin can cancel and do their own judging" | Spec §1.2 non-goal "Decide winners automatically using AI" | ACTIVE |
| D-008 | 2026-10-25 | architecture | ai-provider | Gemini API only, on a normal (free-tier) API key, through `@google/genai` in server routes. Model chain: `GEMINI_MODEL` if set, then `gemini-flash-latest`, `gemini-3-flash-preview`, `gemini-flash-lite-latest` | User decision: Gemini key only, no paid tier, no other provider | — | ACTIVE |
| D-009 | 2026-10-25 | architecture | ai-flow | AI judging scores each design on its own against the rubric, then compares the top N finalists (default 5) side by side to order them. The admin's browser drives one step per request; each step scores one design | Avoids serverless time limits, makes cancel instant, and paces requests under free-tier rate limits | — | ACTIVE |
| D-010 | 2026-10-25 | security | ai-inputs | Gemini receives only the design file, the theme and the rubric. No name, USN or participant code. Text inside a design is treated as data; a design that tries to instruct the judge is flagged | Blind judging; defends against prompt injection written on a poster | — | ACTIVE |
| D-011 | 2026-10-25 | product | ai-visibility | AI judging is internal to organisers. Participants and the public never see AI scores, reasons, flags or which mode was used | User decision | — | ACTIVE |
| D-012 | 2026-10-25 | product | leaderboard | Results are hidden until the admin publishes. Final score: Manual = mean of submitted judge totals; AI = the run's rubric total. Order: AI finalists in their compared order, then by score. Ties: theme → originality → hierarchy → earlier submission. The public board shows rank, participant code, name and score; no comments, no USN | Spec §9.3 fairness controls; tie rules fixed in advance | — | SUPERSEDED |
| D-013 | 2026-10-25 | architecture | live-updates | Clients poll the server every 3 s (participants, projector, admin) and tick the countdown locally from the shared deadline and a measured server-clock offset. No Realtime channel | Simple and reliable for ≤ 200 users; spec §17 forbids polling every second, not every few seconds | — | ACTIVE |
| D-014 | 2026-10-25 | testing | bot-test | `scripts/bot-test.ts` runs a full event with **at least 20** bot participants (it refuses fewer) against local Supabase or a separate test project, never production. It covers the attack cases, the real Gemini AI run (or a dev-only fake judge), cancel, results and publish | User: "bot testing for at least 15–20 members… minimum should be like 20" | — | ACTIVE |
| D-015 | 2026-10-25 | product | judges | Optional judge role. Judges see every submission blind (participant code only), score with the rubric, and see only their own scores. Judges never see AI scores | Spec §3.3, simplified: no per-judge assignment for a single-room event | — | ACTIVE |
| D-016 | 2026-10-25 | design | visual-direction | Dark "studio" editorial: ink background, warm paper text, one signal-orange accent, status colours used only for status. No purple, no gradients-as-decoration | Spec §14.1: expressive but calm under a 10-minute deadline | — | ACTIVE |
| D-017 | 2026-10-25 | product | ranking-order | **Ranks always follow the final score, highest first.** The AI finalist comparison only breaks a tie between finalists with the same score. Then ties: theme → originality → hierarchy → earlier submission. Publishing, visibility and score sources are unchanged from D-012 | User: a 64 ranked above a 71 looked wrong. A published ranking must match the published scores | D-012 | ACTIVE |
| D-018 | 2026-10-25 | architecture | gemini-keys | Gemini calls are routed across a pool of keys (`GEMINI_API_KEYS`, comma-separated, plus `GEMINI_API_KEY`). Each AI step scores up to one design per key in parallel (`ai_next_batch`, cap 8, `GEMINI_PARALLEL`). A key that returns 429 rests for that model for 60 s while the others continue | User: one free key took 10+ minutes for 20 designs because of rate limits. Organisers accept the risk under Google's API terms (no circumventing usage limits) | — | ACTIVE |
